# MuuTask

**Windows のタスクバーの中に**、いま再生中の曲を表示するミニ プレーヤーです。

- タスクバーの空きスペース (アプリのボタン列と通知領域の間) に、
  **アルバム アート + 曲名 + アーティスト・アルバム名 + ⏮ / ⏯ / ⏭ ボタン**が
  並びます。曲名とアーティスト行の間に再生位置バーが出ます。
- **長い曲名は流れます。** 幅に入りきらないときだけ横に送られ、ボタンの裏を
  通って一周します。ボタンは角丸の座を敷いてあるので、文字が通っても読めます。
- 右クリックでメニュー (再生元の切り替え、表示位置、バーの幅、表示設定、終了)。
- 通知領域にもアイコンが出ます。こちらは 16x16 まで縮められてアルバム アートが
  潰れてしまうので、**音符のまま**にしてあります。マウスを乗せると
  「▶ 曲名 — アーティスト (アプリ名)」が出ます。
- 停止中は「再生中の音楽はありません」と表示されます。邪魔なら右クリック
  メニューの**「再生中のときだけ表示」**で、再生中だけ出すようにできます。

Windows のメディア コントロール (音量ポップアップに出るあれ) に対応した
アプリならそのまま扱えます — Spotify、YouTube などのブラウザー再生、
メディア プレーヤー、foobar2000、VLC、AIMP など。

## 使い方

```powershell
powershell -ExecutionPolicy Bypass -File setup.ps1   # 初回だけ
```

そのあとは `run.vbs` をダブルクリックすると、コンソールを出さずに常駐します。
ログを見ながら動かしたいときは `.venv\Scripts\python.exe app.py`。

### 配布用の exe を作る

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1
```

PyInstaller で単体の exe に固めて、配布用の zip までまとめて作ります
(初回は PyInstaller の取得が入ります)。

| 出力 | 中身 |
| --- | --- |
| `dist\MuuTask.exe` | Python なしで動く実行ファイル (onefile / コンソールなし・約 13.6 MB) |
| `dist\MuuTask-<版>.zip` | 配布用。`MuuTask.exe` と [README.txt](README.txt) |

exe には Python 本体 (2.6 MB)・Tcl/Tk・Pillow・WinRT の射影が丸ごと入るため、
どうしてもこの程度の大きさになります。使っていない重い依存
(AVIF コーデック 4.1 MB、OpenSSL 2.1 MB、FreeType 0.9 MB など) は
`build.ps1` の `$excludes` で外していて、これで 21 MB → 13.6 MB です。

版番号は [config.py](config.py) の `APP_VERSION` が唯一の出どころで、zip 名と
[README.txt](README.txt) の `@VERSION@` に埋め込まれます。**`v1` から始めて、
配布物を作るたびに 1 ずつ上げます** (`v1`, `v2`, `v3`, ...)。アイコンは [make_icon.py](make_icon.py) がトレイと同じ音符から
`muutask.ico` を書き出したものを埋め込みます。`dist` と `build` は Git には
入れていません。

### 操作

| 操作 | 動き |
| --- | --- |
| タスクバーの ⏮ / ⏯ / ⏭ | 前の曲 / 再生・一時停止 / 次の曲 |
| バーの上でホイールを回す | システムの音量を上下 (1 ノッチ 2%) |
| タスクバーを右クリック | メニュー (再生元・表示位置・バーの幅・アートの大きさ・表示設定・終了) |
| トレイ アイコンを左クリック | 再生 / 一時停止 |
| トレイ アイコンを右クリック | 同じメニュー |

### 表示位置

右クリック メニューの **「表示位置」** から、タスクバー内のどこに置くかを
3 通りで選べます (即座に反映され、次回起動時も維持されます)。

| 選択肢 | 置き場所 |
| --- | --- |
| 左端 | タスクバーの左端。アイコンが中央寄せなら、スタート ボタンの手前まで |
| スタート ボタンの左 | スタート ボタンのすぐ左に右寄せ |
| 通知領域の左 (既定) | 時計やトレイ アイコンのすぐ左に右寄せ |

タスクバーのアイコンを左寄せにしている場合、「左端」「スタート ボタンの左」は
場所が取れないため、自動的に「通知領域の左」と同じ位置になります。

### 文字送り

曲名とアーティスト行は、**ボタンの手前までに収まっていれば止まったまま**です。
はみ出すときだけ横に流れます (止めたままだと末尾がボタンの裏に隠れたままに
なるため)。流れる範囲はアルバム アートの右からバーの右端までで、ボタンの裏を
通ります。ボタンには地色から少し浮かせた**角丸の座**を敷いてあるので、文字が
裏を通っても記号が読めます。

**一周して先頭に戻ったところで 1 秒止まります。** タイトルとアーティスト行は
長さが違うので、止まる時機は別々に数えています (揃えると片方が中途半端な
位置で止まるため)。同じ曲の間は位置を保ち、曲が変わったときだけ頭に戻します。
送りは 34 px/秒 (96 DPI 基準) で、[app.py](app.py) の 40 ms タイマーが進めます。

座は **50% の網掛け (`stipple="gray50"`)** で敷いています。Tk の Canvas は
項目ごとのアルファ合成ができないため、1 ドットおきに塗ることで実際に裏の
文字を透かしています (原寸では一様な半透明に見えます)。

### ホバーでアルバム アート

バーにカーソルを載せて 0.45 秒待つと、**アルバム アートを大きくした小窓**が
バーの真上に出ます ([art_popup.py](art_popup.py))。タスクバーのボタンに
カーソルを載せたときのプレビューと同じ位置・同じくらいの大きさです。

小窓は最前面に出るので、**右クリック メニューを開くときは消します**
(残すとメニューに覆いかぶさります)。メニューが開いている間は出しません。

大きさは右クリック メニューの **「アルバム アートの大きさ」** から
**標準 (180) / 大きい (300) / とても大きい (430) / 最大 (560)** を選べます
(96 DPI 基準の px。125% 表示なら 1.25 倍に拡大されます)。中間の値にしたい
ときは `config.json` の `popup_height` を直接書き換えてください。
この値は**長辺の上限**です。
**もらえる絵は正方形とは限りません** — YouTube の動画では 150x83 (16:9) が
そのまま来ます (実測)。正方形に切り出すと左右 45% を捨てることになるので、
縦横の比を保ったまま、この大きさに収めます。16:9 なら 400 設定で 400x225 に
なり、小窓もその形になります。Windows 11 のプレビューは
XAML の中で描かれていて**ウィンドウとして掴めない**ため (クラス名で辿れるのは
1x1 の `ThumbnailDeviceHelperWnd` だけで、ホバー時に増える窓も無い)、
実測した値ではなく、超えない範囲の既定値を置いています。

もらえるアートは大きくても 150x150 なので、大きな小窓では引き伸ばすことに
なります。そのままだと JPEG 由来の色ノイズが粒として浮くので、**色だけを
ならしてから引き伸ばし、輝度だけを締め直します** ([icons.py](icons.py))。
色に触らずに輪郭を締めると、なめらかにしたはずの色の縁が立ち直ってしまうため、
順番と対象を分けています。

引き伸ばす前に、**縁の帯も落とします**。YouTube Music は 4:3 のジャケットを
正方形のキャンバスに置いて渡してくることがあり (実測では (18,18,18) の帯)、
そのままだと小窓の中でジャケットが小さくなります。角の色と同じで平らな列を
外側から落とし、絵そのものを食べないよう片側 30% で打ち切ります。

バーの中の小さなアートは**正方形の枠しか無い**ので、こちらは帯を落としたあとに
中央を切り出しています (トレイ アイコンはアルバム アートを使わないので対象外)。

### バーの幅

長い曲名が切れるときは、右クリック メニューの **「バーの幅」** から
**狭い (240) / 標準 (340) / 広い (460) / とても広い (600)** を選べます
(96 DPI 基準の px。DPI に応じて拡大されます)。

置き場所が足りないときは自動的に縮み、`120` 相当を割り込むとバー自体を
出しません。中間の値にしたい場合は `config.json` の `bar_width` を直接
書き換えてください。

### 再生中のときだけ表示

右クリック メニューの **「再生中のときだけ表示」** を入れると、**再生中だけ**
バーが出ます。一時停止・停止中は消えます (この間の操作はトレイ アイコンから
行えます)。既定は切で、停止中も「再生中の音楽はありません」と出したままです。

### ホイールで音量

バーの上でホイールを回すと、**システム全体の音量**が 1 ノッチ 2% ずつ上下します
(Windows 標準の音量表示もそのまま出ます)。切りたいときは右クリック メニューの
**「ホイールで音量を調整」** を外してください (既定は入)。

このバーはフォーカスを持たないため、ホイールは**低レベル マウス フック**で
拾っています (→ [仕組み](#仕組み))。バーの矩形の外や、バーが何かに覆われて
いるときは横取りせず、そのまま下のウィンドウへ流します。

### 自動起動

エクスプローラーのアドレス バーに `shell:startup` と入力して開いたフォルダーへ
`MuuTask.exe` への**ショートカット**を置くと、ログオン時に自動で常駐します。

exe 本体を移動した場合は、リンクが切れるのでショートカットを作り直します。
アプリ側にこの設定を持たないのは、レジストリに何も書かないためです
(→ [レジストリと設定ファイル](#レジストリと設定ファイル))。

複数のアプリが同時に音を出しているときは、既定では「いま再生中のアプリ」を
自動で追いかけます。特定のアプリに固定したい場合はメニューの **「再生元」**
から選んでください。

## 仕組み

- 再生情報は Windows の `GlobalSystemMediaTransportControlsSessionManager`
  (WinRT) から取得しています。曲・アーティスト・アルバム アート・再生位置・
  操作可否まですべて OS 側から受け取るため、プレーヤーごとの対応は不要です。
- WinRT の呼び出しは専用スレッドの asyncio ループで行い、変更通知は
  イベント + 1 秒ごとの保険ポーリングで拾っています ([media_session.py](media_session.py))。
  この監視スレッドが止まると、**表示も操作も凍りついたまま二度と戻りません**
  (→ [監視が止まらないようにする](#監視が止まらないようにする))。
- **アルバム アートは曲名より遅れて届きます。** 曲が変わった瞬間に読むと、
  前の曲の絵や途中の別画像が返ってきます (実測では 0.5 秒ほど遅れて本来の
  画像に差し替わりました)。そのため曲が変わってから 8 秒間は 0.3 秒ごとに
  読み直し、中身が変わっていれば拾い直します。
- **同じ絵が、大きい方から小さい方へ順に届きます。** Chrome の YouTube Music
  (PWA) で実測した並びは、曲を切り替えてから

  | 届く順 | 中身 | 大きさ |
  | --- | --- | --- |
  | 1 | ブラウザーのアプリ アイコン (Chrome ロゴ) | 256x256 |
  | 2 | アルバム アート | 150x150 |
  | 3 | 同じアルバム アート (JPEG で畳み直したもの) | 120x120 |

  で、2 と 3 の間はわずか 0.2〜0.4 秒です。3 は色ノイズの乗った粗い絵なので、
  受け取ってしまうと小窓が汚くなります。**いま持っているものと同じ絵で、かつ
  小さいものは見送ります**。1 は曲名がまだ空のうちに来るので、名無しの間は
  アートを受け取らないことで避けています (前の曲のアートを出したままにする)。
  **SMTC には大きさを要求する口が無く**、載せる絵はアプリ任せなので、150x150
  より大きいものはもらえません。ログアウト状態の Firefox に至っては、
  YouTube Music でもアートも曲名も渡してきません (実測)。
- **Firefox はシークした直後に「長さも位置も 0」のタイムラインを送ってきます。**
  Google からログアウトした状態の YouTube / YouTube Music で実測しました。
  正しい位置が 1 度届いた 0.25 秒後に、再生中のまま空のタイムラインで
  上書きされます (`last_updated_time` も今の時刻に更新されるので、古い報せとして
  見分けることもできません)。素直に受け取ると曲の途中なのにバーが頭に戻り、
  一時停止して再生し直すまで戻りません。長さの分かっている曲で空が来たときは
  届かなかったものと見なし、直前の値を進め続けます。
- **ホイールは低レベル マウス フック (`WH_MOUSE_LL`) で拾っています**
  ([winapi.py](winapi.py))。バーは `WS_EX_NOACTIVATE` でフォーカスを持たないため、
  `WM_MOUSEWHEEL` は届きません。Windows はホイールをフォーカスのあるウィンドウへ
  送り、「非アクティブ ウィンドウをホバー時にスクロールする」が入っているときだけ
  カーソルの下へ送るからです。この設定に左右されないよう、フックで拾って
  カーソルがバーの矩形の中にあるときだけ握り潰しています。フックの処理は入力の
  流れを止めるので、中では位置の判定と音量キーの送出しか行いません
  (時間がかかると Windows にフックを外されます)。音量そのものは
  `IAudioEndpointVolume` を COM で掴まず、`VK_VOLUME_UP` / `VK_VOLUME_DOWN` を
  送るだけにしています。既定の再生デバイスの選び直しを OS に任せられ、
  Windows 標準の音量表示も出るためです。
- 画面はダーク / ライトと **Windows のアクセント カラー**、高 DPI に追従します
  ([theme.py](theme.py))。

- タスクバーへの表示は、**タスクバーと同じ高さ・同じ地色の最前面ウィンドウ**を
  空きスペースにぴったり重ねて実現しています ([taskbar_bar.py](taskbar_bar.py))。
  0.25 秒ごとにタスクバーの位置・高さ・通知領域の左端を測り直して追従します。
  タスクバーをクリックするとタスクバー自身が持ち上がってバーが潜るので、
  `WindowFromPoint` で覆われたかを判定し、覆われていれば前に出し直します。
  地色はその場所のピクセルを実際に読んで合わせています。**一色ではなく行ごと**に
  読んで同じ並びを描き写しているので、タスクバー上端の細いハイライト
  (実測で `#434346`、本体は `#212126`) がバーの上でも途切れません。
  一色で塗ると、そこだけ塗り潰されて浮いて見えていました。
  `MUUTASK_DEBUG=1` を設定して起動すると、この追従処理のログが出ます。

| ファイル | 役割 |
| --- | --- |
| [app.py](app.py) | 起動と各部品の接続、スレッド間の受け渡し |
| [media_session.py](media_session.py) | WinRT のメディア セッション監視・操作 |
| [taskbar_bar.py](taskbar_bar.py) | タスクバーに重ねるバー |
| [art_popup.py](art_popup.py) | ホバーで出るアルバム アートの小窓 |
| [tray_icon.py](tray_icon.py) | トレイ アイコンとメニュー |
| [icons.py](icons.py) | アルバム アート / 音符アイコンの描画 |
| [theme.py](theme.py) | テーマ・アクセント カラー・DPI |
| [winapi.py](winapi.py) | タスクバーの位置取得・最前面維持などの Win32 呼び出し |

### 監視が止まらないようにする

メディア監視のスレッドが死ぬと、**バーは最後の曲を映したまま固まり、ボタンも
効かなくなり、何をしても戻りません**。実際に v9 でこれが起きました。凍った
プロセスのスタックを取ると `muutask-media` スレッドだけが消えていて、監視の
周回が `except OSError` しか持っていなかったのが原因でした。相手のアプリは
曲を切り替えるたびにセッションを作り直すので、閉じかけのセッションを触ると
`OSError` 以外の例外も飛んできます。それが 1 回抜けただけでスレッドごと
終わり、`_loop` が `None` になってボタンの要求も捨てられる、という筋道です。

そのため監視は次の三重で守っています。

- **周回は何が飛んできても続ける。** 例外は握り潰さずログに残し、3 回続けて
  転んだらセッション マネージャーごと取り直します。
- **待ちっぱなしを作らない。** WinRT の各呼び出しに 5 秒、1 周ぜんたいに
  20 秒の上限を設け、返ってこない相手は見捨てて先へ進みます。
  `asyncio.wait_for` は使えません — pywinrt のラッパーは取り消されると
  `IAsyncOperation.cancel()` を呼んでから**完了を待ち直す**ので、応答しない
  相手だと取り消しごと固まります。`asyncio.wait` で待つのをやめるだけにします。
- **それでも落ちたら立て直す。** ワーカーが終了したらスレッド側で 1 秒待って
  ループを作り直します。諦めるのは終了するときだけです。

閉じかけのセッションは `get_playback_info()` / `get_timeline_properties()` が
**`None` を返してきます** (実測。v13 のログには 1 日で 5 回残っていました)。
例外にして周回ごと転ばせると、3 回続いたときにセッションを張り直すことになり、
アルバム アートも覚えている再生位置も捨ててしまいます。捨てた直後に Firefox の
空タイムラインが来ると、直したはずのバーがまた頭に戻ります。そのため読めない
周回は静かに飛ばし (表示が 1 秒ぶん古くなるだけ)、5 回続いたときだけ張り直します。

追いかける対象はアプリ ID ではなく**セッションそのもの**で見比べます。同じ
アプリでも曲を変えるとセッションは作り直されるため、ID で見ていると閉じた方を
掴んだままになり、イベントも届かず、ボタンの宛先も失われます。

想定外の例外が出たときだけ、config.json と同じフォルダーに `MuuTask.log` を
書きます ([errlog.py](errlog.py))。ふだんは作られません。

### 常駐メモリ

起動から 5 秒後と、以後 10 分ごとに `SetProcessWorkingSetSize(-1, -1)` で
常駐ページを OS に返しています ([winapi.py](winapi.py))。import・Tk の初期化・
onefile の展開など**起動時にしか触らないもの**がそのまま常駐し続けるためで、
実測では本体プロセスが **66 MB → 14 MB** になりました (合計 76 MB → 23 MB)。
捨てるのは物理メモリ上の常駐分だけなので、必要になれば読み直されます。

残りの 8.5 MB は onefile の親プロセス (展開して子を起動する殻) です。
`--onedir` にすればこのプロセスごと無くなり、起動時の展開も不要になりますが、
配布物が exe 1 つではなくフォルダー一式になります。

### レジストリと設定ファイル

**レジストリには一切書きません。** 設定は `MuuTask.exe` と同じフォルダーの
`config.json` に置くので、やめるときはフォルダーごと削除すれば痕跡が
残りません (ソースから動かしているときは [config.py](config.py) と同じ階層)。
書き出すファイルはこれと、想定外の例外が出たときだけ作られる `MuuTask.log`
の 2 つだけで、どちらも同じフォルダーに置きます。
書き込めない場所 (Program Files 直下など) に置かれた場合は保存を黙って
諦め、その回の変更は効いたまま次回起動時に既定値へ戻ります。

読み取りだけはレジストリを使います — ダーク / ライトとアクセント カラーを
`HKCU\...\Themes\Personalize` と `...\DWM` から読む部分です
([theme.py](theme.py))。書き換えはしません。

v1 が `%APPDATA%\MuuTask\config.json` に残した設定があれば、起動時に新しい
場所へ移してから旧フォルダーを消します (空でなければ `rmdir` が失敗するので、
自分以外が置いたものは残ります)。

バーの見た目は次の項目で調整できます (書き換えたらアプリを再起動)。

| キー | 既定値 | 意味 |
| --- | --- | --- |
| `bar_anchor` | `"tray"` | 置き場所。`"left"` / `"start"` / `"tray"` |
| `bar_hide_when_idle` | `false` | 再生中のときだけ出す (既定は停止中も出しっぱなし) |
| `bar_width` | `340` | バーの幅 (96 DPI 基準の px。DPI に応じて拡大) |
| `bar_gap` | `8` | 通知領域との間隔 |
| `bar_bg` | `null` | 地色を固定したいとき (`"#202020"` など) |
| `popup_height` | `180` | ホバーで出るアルバム アートの長辺の上限 (96 DPI 基準の px。メニューからも選べます) |

## 制限

- Windows 11 は公式のタスクバー拡張 (ツール バー / デスク バンド) を廃止しており、
  `SetParent` でタスクバーの子ウィンドウにする従来の方法も、現在のビルドでは
  エラー 87 で拒否されます (他プロセスのシェル ウィンドウへの再親子付けが
  塞がれている)。そのため本アプリは **タスクバーに重ねる最前面ウィンドウ**という
  方式を取っています。見た目はタスクバーの中に入っていますが、内部的には
  タスクバーの一部ではありません。
- **スタート メニューを開くとバーがタスクバーの後ろに隠れ、閉じただけでは
  戻りません。** 何かウィンドウをクリックする (アクティブにする) と戻ります。

  スタート メニューを開くと、タスクバー (`Shell_TrayWnd`) は z バンドが
  **1 → 6 (`ZBID_IMMERSIVE_EDGY`)** に上がります。そして**スタート メニューを
  閉じてもバンドは 6 のまま**で、別のウィンドウが活性化されるまで下りてきません
  (実測。フォアグラウンドが元のアプリに戻っていても下りません)。上のバンドへは
  `SetWindowPos` では入れず、`SetWindowBand` は UIAccess 権限
  (署名 + 信頼された場所へのインストール) が無いと `ERROR_ACCESS_DENIED` で
  弾かれます。オーナー設定 (`GWLP_HWNDPARENT`) も他プロセスのウィンドウには
  効きません。**ユーザー権限のアプリからは回避できない**ため、この間は要求を
  出さずに待ちます。バンドが 1 に戻れば 0.25 秒以内に復帰します。
- バーは通知領域の左隣に置かれます。起動中のアプリが多くてタスクバーが埋まると
  アプリのボタンと重なることがあります。その場合はメニューの「バーの幅」を
  狭くしてください。
- 全画面のアプリ (ゲームや動画) が前面にあるときは、バーは自動的に隠れます。
- 管理者権限で動いているアプリが前面にあるときは、ホイールでの音量操作が
  効かないことがあります。ユーザー権限のフックは、より高い権限のウィンドウへの
  入力を受け取れないためです (UIPI)。
- マルチ ディスプレイでは、メインのタスクバーにのみ表示されます。
- 再生位置バーは表示専用です (シーク機能はありません)。右端の縦の目印が
  曲の終わりです。
- ダーク / ライトとアクセント カラーは起動時に読み込みます。変更した場合は
  再起動してください。
